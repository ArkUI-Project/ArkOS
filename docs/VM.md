# ArkOS 0.13.0 虚拟内存

匿名内存由 ArkOS 自研 x86-64 内核管理。预留、首次缺页分配、回收与磁盘换入换出都发生在客体内；QEMU 只提供被驱动的内存与磁盘设备。交换数据存入 ArkOS 数据卷的内核私有二进制区，不依赖宿主交换文件。

## 使用接口

`SYS_VM=42` 接受清零的 `ArkVMRequest` 和准确结构长度。应用只能操作自己进程的匿名区，线程共享 owner 的页表与统计。地址范围为 `0x60000000..0x7e000000`，每进程最多 128 个区间；普通进程总预算 64 MiB，SYSTEM 512 MiB，ELF、栈和匿名区预留共同计费。

| 操作 | 输入与结果 |
|---|---|
| RESERVE=0 | bytes>0，向上按 4096 对齐，返回 address/bytes；仅占虚拟区间和页表，物理页尚未分配 |
| COMMIT=1 | address/bytes 按页对齐且在已预留区间内；flags 至少 READ，可加 WRITE；第一次访问时分配清零物理页 |
| DECOMMIT=2 | 撤销提交并释放驻留页和交换槽，保留虚拟区间；重新 COMMIT 后读到零 |
| RELEASE=3 | 必须是完整预留区间；释放物理页、交换槽、虚拟区间及预留预算 |
| PROTECT=4 | 改变已提交匿名页的 READ/WRITE，所有匿名页保持 NX；不接受执行权限 |
| QUERY=5 | 返回 owner 的预留/提交/驻留/已交换字节、缺页和换页累计数，以及实际物理池/空闲/已分配交换区容量 |
| TRIM=6 | 将范围内已驻留匿名页写到客体盘并回收；resident_bytes 返回本次换出的字节数，部分成功后遇错仍返回 -5 |

`ark_memory(bytes)` 保留 SYS_MEMORY=38 的 scalar 调用约定，内部执行预留加 READ|WRITE 提交，单次最多 64 MiB。`ark_memory_release(pointer,bytes)` 将长度向页边界取整，释放完整区间。应用根据自己保留的原始分配长度调用，不能拆除 ELF 或栈。

```c
ArkVMRequest r = {.op=ARK_VM_RESERVE, .bytes=8u*1024u*1024u};
if (ark_vm(&r) < 0) return 1;
uint64_t base=r.address, length=r.bytes;
r=(ArkVMRequest){.op=ARK_VM_COMMIT,.flags=ARK_VM_READ|ARK_VM_WRITE,
                .address=base,.bytes=length};
if (ark_vm(&r) < 0) return 1;
volatile unsigned char *data=(void *)(uintptr_t)base;
data[0]=42; /* 客体 CPU 的首次写入触发实际物理分配。 */
r=(ArkVMRequest){.op=ARK_VM_RELEASE,.address=base,.bytes=length};
int64_t result=ark_vm(&r); /* 检查错误；并发线程可能需要先进入等待。 */
```

错误为 -22 非法区间/对齐/操作、-14 请求指针无效、-12 虚拟预算/区间/物理资源不足、-16 同一 owner 仍在其他 CPU 运行、-5 交换读写或校验失败。RELEASE/DECOMMIT 的目标不能包含正在使用的请求结构。预留预算是实际上限，交换不会扩大它。

## 页表、回收与磁盘

每进程独立 CR3，用户匿名页为 4 KiB；标记区分已预留、已提交和已交换页。用户访问或经过权限检查的系统调用复制会解析可用的提交页。未提交访问、写只读页或从匿名页执行代码是保护错误，只结束违规进程，其他进程继续运行。

物理页池从 128 MiB 起，按客体 RAM 选择容量，最多 896 MiB。分配不足时采用带 accessed 位的第二次机会扫描，最多两个池轮次。只有匿名页可换出；ELF、栈、页表、驱动/DMA 和内核缓冲保持驻留。进入系统调用复制的 owner，以及其他 CPU 正在运行的 owner，不作为回收目标；用户缺页时可回收当前进程的其他匿名页。

交换槽上限 16384 个，即 64 MiB；数据卷实际可用空间和 COW 两代引用可能更早限制容量。每 32 页组成 128 KiB 的 `@swap.N` 私有对象，公开 BLOB 无法列举、读取或写入。分配使用真实 ArkFS 区段与 COW 索引，不覆盖账户、应用包、配置或用户文件。页写入并 flush 成功后才撤销驻留映射。换入检查槽 owner、虚拟地址和页内容摘要；读写失败保留原有效页或交换槽。摘要用于错误检测，不是恶意磁盘篡改认证。

活动页与槽身份只在当前启动内有效；交换区不是休眠镜像。重启不恢复旧进程，旧区段会按当前新槽先写后读。释放和进程退出回收槽；物理页再次分配前清零。交换数据没有加密。

## 多核边界

内核入口由全局锁串行化。匿名区释放、撤销提交、降权和主动回收在同进程的其他 CPU 仍执行用户代码时返回 -16。提交新的非驻留页可进行，改变已提交页权限同样检查远端活动。当前 CPU 更新页表后执行 invlpg；本版没有任意并发拆映射或远端 TLB shootdown。调用者需要让其他线程进入等待，再检查实际操作结果。

## 已运行验证

`tests/vm_memory_test.py` 使用生产分页、ArkFS、块驱动和服务代码构造独立诊断镜像。BIOS/UEFI 实际 x86 CPU 访问验证：首次清零、按需驻留、跨 syscall 的缺页解析、TRIM 磁盘换出/换入、数据摘要、释放/重用、撤销后重新清零、非法指针/长度，以及只读、未提交、NX 违规进程隔离。耗尽真实物理池后仍可自动换出并读回数据，原文件保持原文。

QEMU blkdebug 真正拒绝底层 write_aio 的失败检查通过，驻留页与原文件保持有效。当前 AHCI 错误策略会把错误设备标记不可用，后续交换和磁盘操作也会失败；系统不会报告写盘成功。载荷摘要、串口与保护探针结果保存在各次测试输出目录，入口见[开发指南](../CONTRIBUTING.md)。ARM64 尚无本模块。
