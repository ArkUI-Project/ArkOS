# ArkOS 源码结构

当前 x86-64 目标使用 Multiboot2/GRUB 启动自研内核，桌面和独立应用
运行在 Ring3。目标机内执行驱动、存储、网络、字体、输入法、GPU
材料和应用；主机工具负责构建与测试。接口与资源边界见
[API](API.md)和[开发指南](../CONTRIBUTING.md)。

## 目录

| 目录 | 内容 |
|---|---|
| `boot/` | x86 引导、AP 启动、内核链接布局和 BIOS/UEFI GRUB 配置 |
| `kernel/` | 调度、私有页表、系统调用、驱动、文件系统、网络与持久化服务 |
| `include/` | 内核接口、公共 ABI、ArkUI 与稳定应用目录 |
| `user/` | 可信桌面、窗口/菜单/Dock/设置模块、字体、动效和输入法 |
| `user/apps/` | 十一个独立链接的 Ring3 应用 |
| `sdk/` | 应用窗口、事件、文件、配置、线程、拖放及示例 |
| `arm64/` | 独立 ARM64 串口开发目标 |
| `assets/` | 固定字体源数据与许可 |
| `runtime/wasm/` | 客体 WASM 移植层、原生受限导入和内置样例 |
| `third_party/` | 固定上游源码、协议、数据、许可证与修改记录 |
| `scripts/` | 构建、镜像、启动、字体/词典生成和版本打包工具 |
| `tests/` | 主机边界检查、独立磁盘构造和真实客体测试 |
| `docs/` | 接口、源码结构、存储、网络和开发说明 |

构建输出和本地客体数据位于 `build/`，由 `.gitignore` 管理。
完整源码构建入口为 `Makefile`；`user.mk`、`net.mk`、`wasm.mk` 与
`arm64.mk` 定义相应子目标。普通构建使用已捆绑的固定组件。

## 运行边界

内核从实际进程身份推导 UID 和权限，验证用户指针、整数范围和对象
生命周期。进程持有私有页表与 W^X/NX 映射；匿名内存支持按需分页，
内存紧张时使用客体 ArkFS 交换。详见 [VM](VM.md)。

`user/desktop.c` 与 `desktop_*.inc` 组成可信桌面。它持有 SYSTEM
权限，管理窗口、输入路由、系统工具与呈现；独立应用经受检查的
surface 和系统调用访问服务。一个进程可拥有多个窗口，系统关闭
按钮结束所属应用，最小化保留进程。应用目录和系统包源清单由
`include/ark_catalog.h` 定义。

主显示采用 VMware SVGA 或引导帧缓冲；原生 VirtIO-GPU/VirGL
执行固定玻璃着色，CPU 路径继续负责其他绘制与最终合成。UTM GPU
配置使用专用现代 VirtIO-serial 原生鼠标通道，输入仍经过按设备
状态、按下/松开与触摸仲裁。材质和输入接口见 [API](API.md)。

字体直接使用 `assets/fonts/wqy-microhei.ttc` 的固定轮廓，运行时在
客体按实际字号光栅化。全拼使用固定 Rime/OpenCC/Unihan 派生词典
和按用户保存的个人学习。许可与原始数据见对应资源目录。

## 验证

主机测试检查存储、输入、数学、ABI、权限和资源边界；客体测试检查
实际启动、CPU 保护、设备 DMA、图形交互、网络与持久化。独立夹具
通过源码生成，并在各测试自己的输出目录中使用。验证记录对应
实际镜像摘要与测试范围，保存在各自的构建与发布目录；入口见
[开发指南](../CONTRIBUTING.md)。ARM64 的当前范围是串口开发
与 EL0 自检，完整 x86 桌面仍属于 x86-64 目标。
